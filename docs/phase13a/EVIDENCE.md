# Phase 13A Evidence

Local evidence generated by `scripts/generate_phase13a_evidence.py` covers:

- Phase 13A Python contract tests;
- exact dependency-lock validation;
- source-contract validation;
- deterministic unsigned Linux developer package;
- sandboxed Linux install/uninstall smoke;
- release-gate evaluation proving unresolved mandatory rows remain blocked.

Signing, notarization, clean-OS installers, and commercial DAWs are external mandatory evidence and remain unresolved until their target workflows execute.

Current macOS wrapper evidence is recorded in `.omo/evidence/phase13a-wrapper-build.md`.
The clean pinned VST3 artifact was exercised with the official Steinberg VST 3.8.1
validator and passed 47/47 tests (exit 0). The AUv2 component was temporarily
installed in the real user Audio Unit location and passed `auval` (exit 0); the
temporary component was then moved out and is no longer installed. The release
gate remains blocked.

The format builder can now ingest those schema-versioned validator result files
with `--vst3-validation-result` and `--auval-validation-result`. It binds every
`PASS` to the freshly built bundle tree hash and records the evidence paths in
the format release manifest. The exercised result is recorded in
`.omo/evidence/phase13a-validation-ingest.md`; the format-only manifest was
`READY`, while the overall External Beta release remains blocked.

The macOS Developer ID plugin payload signing path was also exercised against a
temporary copy. It refreshes signature-dependent wrapper manifests, preserves
the exact signed artifact hashes, and reruns the official VST3 validator and
registered `auval` successfully. Details are recorded in
`.omo/evidence/macos-signed-plugin-validation.md`; notarization and clean-OS
installer evidence remain unresolved.

The signed distribution workflow validates after payload signing and before PKG
assembly, so its validator records bind to the delivered plugin bytes rather
than the pre-signature build.

The unsigned format workflow and the signed Windows/macOS distribution
workflow now preserve a self-authenticating VST3 packet. Each packet binds the
validator result and raw stdout/stderr, validator binary, signed or unsigned
VST3 tree, canonical CLAP tree, runner metadata, and build manifest. Packet
integrity does not promote a validator `FAIL` or `NOT_RUN` result; it only
proves which bytes were observed.

Target-runtime packet verification is now fail-closed on schema, platform,
build-state, runtime result, and hash-bound runner metadata, and rejects
symlinked artifacts. The record writer enforces the same source boundary. The
Usable Alpha contract verifier likewise rejects symlink components in
repository evidence. These checks strengthen evidence integrity but do not
turn the target-runner rows from `NOT_RUN` into runtime `PASS`.

The Windows signed workflow now performs the same sequencing: Authenticode
signing refreshes the VST3 wrapper manifest, the official Windows VST3 validator
checks the signed tree with expected CLAP/VST3 hashes, and the evidence is
attached before NSIS installer assembly. Target Windows execution remains
unrun in this environment.

The Linux VST3 wrapper path has an arm64 LinuxKit preflight record under
`.omo/evidence/phase13a-vst3-linux/`. That build exposed and fixed three
portable contract defects: the shared module needed PIC, the format builder
needed to search `SEAM_ARTIFACT_DIR`, and the pinned `clap-wrapper` checkout
ignored a non-empty `CLAP_PATH` on Unix. The wrapper reached a complete build;
the first validator attempt correctly failed with `GetPluginFactory returned
nullptr`, which led to the CLAP-path patch. A post-fix validator rerun was not
completed after the local Docker filesystem became inconsistent and exhausted;
the Linux target remains `NOT_RUN` rather than being promoted from local
preflight evidence.


Checked-in local evidence is stored at `evidence/local-engineering-validation.json`.
It records 39/39 CTest, 128/128 named C++ tests, 33/33 Phase 13A Python
tests, artifact hashes, and the explicit `NOT_RUN` external mandatory rows.
It is engineering evidence only and cannot promote a release gate.
