# Procedural candidate v1

Vowel classification now uses the shared phonemizer vocabulary, including English
stress-marked symbols and Korean vowels such as `eo` and `eu`. Every marker must
still resolve to its exact recipe phone/style pose and a valid tract at the
candidate's sample rate. A supported symbol is not pronunciation qualification.

Vowel-only exports retain this format. Mixed oral-vowel/frication exports use [candidate v2](PROCEDURAL_CANDIDATE_V2.md), including explicit gesture kinds and articulation revisions; both versions use the strict loader and canonical producer transaction.

Latest native intake state: background import is now implemented (see the final section). Earlier synchronous-handler notes below describe previous checkpoints.

Explicit `ExportSettings::includeProceduralCandidates` bakes one candidate per nonempty procedural region through the same Final-quality snapshot pipeline used for rendering. It defaults to false and may be used without master/stem outputs. The operation includes the source project/recipe snapshot and does not modify the working project, approve material, install a bank or infer redistribution rights.

Files are `candidates/<track-id>-<region-id>.wav` and a matching `.json`, committed with the export set's existing staging/journal/receipt transaction. WAVs are mono Float32, starting at their first stored sample rather than padded from song frame zero. The metadata records:

- `formatId`: `com.project-seam.procedural-candidate`; integer `schemaVersion`: 1.
- `approval`: `unapproved`; `markerSemantics`: `planned-vowel-gestures`.
- Exact `audioSha256`, `sampleRate`, `frameCount`, and absolute `scoreOriginFrame`.
- `renderContentHash`, `renderAbi`, `proceduralRevision`, and `compilerRevision`.
- `recipeId`, `recipeVersion`, `recipeHash`, and `style`.
- `markers`: phoneme `key`, `phone`, and half-open `startFrame`/`endFrame` relative to the candidate WAV. These describe planned gestures, not measured acoustic boundaries or F0.

The enclosing receipt records every candidate/source file digest and `includesProceduralCandidates`. Candidate baking captures and verifies the recipe once before rendering. Limits are 256 candidates, 65,536 aggregate score notes, 16 MiB unique recipe bytes, and 1,024 total export files. Existing per-phrase PCM/input bounds remain enforced. Unknown/duplicate source tracks reject before staging. All procedural regions are included when explicitly requested, including muted ones; sample-bank regions are not converted into procedural candidates.

The current supported inventory is oral vowels, with shared timing, crossfades and within-note edited spans. Unsupported consonants or extended timing fail rather than receiving false labels. Mono candidates omit project mixing/pan, but retain compiled note expression. Sample banks/backing audio are not bundled by the source-snapshot option.

## CLI import

```text

```

`WORKSPACE` is an existing native producer repository with a qualified procedural source strategy and matching inventory assignment. `METADATA`/`WAV` identify the baked candidate; `RECIPE` is its exact recipe JSON. ## Native producer import

Cancellation contract: controller and repository candidate intake accept an optional stop token. It reaches recipe/candidate validation and is checked before asset import, after asset import, and immediately before the first durable journal write. Pre-commit cancellation does not publish a take or advance the durable generation; repository rollback restores staged in-memory changes when save rejects. Once journal publication starts, the normal commit result is authoritative and later cancellation does not relabel a saved take as cancelled. Unreferenced asset bytes may remain if cancellation arrives after asset copying. Asset-store copy/hash operations and recovery verification are still synchronous within their stage, so this is cooperative cancellation, not a bounded-latency guarantee. The native dialog handler has not yet moved to a worker. Tests cover already-requested cancellation in save, repository import and controller import, including unchanged generation, metadata, inspection/status and no initial asset creation; mid-commit cancellation timing is not runtime-qualified.

Repository saves serialize cooperating writers using a persistent `.writer.lock` file and an OS-owned exclusive lock. The lock is released on close/process exit; the file must not be deleted as routine cleanup. After acquiring it, saving checks the caller's project identity and durable generation against the latest valid recovered generation. Busy/unsafe locks and stale callers return Conflict without publishing a new generation. Callers must recover current state and reconcile their intended edit, not blindly retry a stale object. Incomplete later journals remain occupied and are skipped when assigning the next generation. This protects repository commits; it does not make the native controller thread-safe or implement asynchronous intake. Pre-commit asset imports may still leave unreferenced content-addressed assets after failure.

In Voicebank Studio, open the production workspace with its expected inventory digest and operator, select an inventory row, then use Cmd/Ctrl+I. Choose candidate JSON and its exact recipe JSON; the paired WAV is the metadata file's same-stem `.wav` sibling. Occupied rows are explicitly presented as retakes. Active or unfinished recording prevents import. Cancellation at either dialog changes nothing.

The controller imports through the strict repository path, retains lineage, leaves the new take in MarkerReview and clears any earlier dry-take inspection. A session epoch advances on every successful workspace open. The application validates epoch, durable generation and selected row after each dialog; same-content reopening also invalidates the interaction. These are same-controller interaction guards, not transferable authorization tokens.

Current verification: strict Debug/Release controller/export integration builds and all 15 cases pass (1.44/0.61 seconds), and the Release native Studio executable builds. Tests cover actual controller import/recovery, status/review state, inspection clearing and stale row/session/generation checks. This finishes the implementation interrupted before its documentation update. Actual native dialog interaction, focus/accessibility behavior and import responsiveness were not exercised. ## Background native intake

After the existing modal context checks, Studio calls `beginProceduralCandidateImport`. The controller snapshots the producer project, resolved inventory assignment and operator into a worker-owned controller/repository. Recipe loading, verification, asset import and durable save run there. No worker reads or changes the live controller. The owner thread polls the future without waiting; after success it adopts the committed producer state and clears old inspection. Existing staged-operation counts are retained because candidate import does not alter staged operations.

While the future is pending (including completed-but-uncollected results), managed selection, open, save, inspection, marker/pitch editing, producer operations, export and repeat imports reject. The native app also prevents recording and pointer edits. Resizing/painting remain available. The status identifies the active import; Escape requests cooperative cancellation. Failure restores the earlier status and retains inspection/project state, with the error returned through the existing app error channel. External writers are handled by the repository's durable-generation conflict check, not by these UI guards. Recovery/reconciliation after such a conflict remains explicit.

The native paint loop polls completion and requests another frame while busy. Shutdown requests cancellation, joins and collects the actual result before printing final producer diagnostics. Destruction also requests cancellation and waits for the owned worker; no detached work retains UI pointers. A late cancellation may still produce success if publication has crossed the commit boundary. Filesystem-stage cancellation latency remains unbounded by this implementation, and native dialog/focus/responsiveness plus Windows runtime behavior still require direct qualification.
