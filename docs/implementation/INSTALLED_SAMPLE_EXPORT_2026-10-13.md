# Signed installed sample operation export

2026-10-13. Integrating base: `5fb5da639c005900b09e6d1f882a2072c41db1e2`. [Evidence index](INSTALLED_SAMPLE_EXPORT_2026-10-13.evidence.json). Technical review pending. This is an engineering unit; it admits no internet recordings or human decisions.

## Problem and resulting behavior

The native installed operation command previously supported recipes only. A signed sample installation could be audited and bound to a saved project, but could not produce an observed native operation record. Ordinary sample rendering froze its WAV and optional sidecar bytes without comparing them to the entries just verified by the installation auditor. A later substitution could therefore produce a different selection or sound under the same persisted resource identity.

`export-installed-sample-project PROJECT SHA TRACK REGION LANGUAGES PACKAGE PACKAGE_SHA CANDIDATE_SHA INSTALLED PUBLIC_KEY OUTPUT_DIRECTORY` now verifies the signed package and installed tree, captures the project with its native codec, requires exact sample id/version/content pins on every vocal track (including muted tracks), and checks each note-linked language against the signed declaration. It then runs the existing Final export transaction with automatic interrupted-set recovery disabled. Recipe export retains its own family restriction and operation record. Model installation and operation capture, backing-media attestation, human listening and release qualification remain unavailable here.

## Code boundary

`verifyInstalledResourceCandidate` parses the sample manifest from the same private package snapshot used for signature, descriptor, receipt and installed-tree verification. Its result carries that manifest and a shared immutable map of signed relative entry paths to encoded-byte SHA-256 digests. The map does not confer trust by itself: the native operation gets it from independent package verification, with explicit trusted signer keys. The existing verification JSON remains unchanged.

`TrackVoicebankSource` carries an optional expected-entry map through `ProductionProjectRenderer` and `ProductionRegionRenderer`, including recursive polyphonic projections. `RenderSnapshotFactory::create` compares each held WAV's digest before decoding, and checks the exact text/bytes of consumed alignment and acoustic-analysis sidecars before parsing. A signed optional sidecar must be present; an unsigned extra sidecar cannot enter the render. The selection eligibility probe also refuses a missing signed alignment before treating a multi-phone competitor as ineligible. Losing eligible competitors are guarded because they influence selection. The existing frozen decoded buffers and sidecars then serve rendering and cache identity; the pipeline does not reopen them after capture. File changes after capture cannot change an already frozen snapshot.

No expected map means the existing caller-owned authoring behavior. This unit does not claim every GUI preview has acquired signed admission. Metadata pin checking remains separate from byte capture, and unused package entries are not independently frozen for rendering. The initial installed-tree audit covers the package entry set; the operation capture assertion covers assets actually consumed by selection and rendering.

The new `seam.u45.installed-sample-export.v1` record binds the captured project, verified installation, build/host/platform, declared project languages, actual writer-held artifact hashes, independently re-observed published bytes, export receipt SHA, master SHA and the writer's pre-encoder peak/clipping measurements. It reports `SIGNED_ENTRIES_MATCHED_FROZEN_SAMPLE_ASSETS`, `NATIVE_FINAL_EXPORT_SET` and engineering scope. Executable identity still requires an external pin. `playback`, `dawExecution` and `humanAcceptance` stay `NOT_RUN`; `qualification` stays `NOT_QUALIFIED`; release flags stay false. There is no closed operation-record replay validator in this increment, and no U45 hold is lifted.
