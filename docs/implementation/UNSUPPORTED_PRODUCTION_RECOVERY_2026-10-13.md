# Refuse unsupported production history during recovery

Date: 2026-10-13, Asia/Seoul. Base: `67a031573b91a0f03b215166ec5aa2498be18e89`. [Evidence index](UNSUPPORTED_PRODUCTION_RECOVERY_2026-10-13.evidence.json) binds six exact tested/base sources in a format-classification follow-up, with the original five-pair evidence preserved, baseline/final executables and raw logs. Technical review is APPROVE for 394a29b8; later follow-ups are separately scoped.

`ProductionProjectRepository::recover` previously skipped every failed generation and returned the first older valid one. An unsupported newest project schema or inspection-policy journal was therefore treated like damaged supported data. Studio's `openProductionProject` installed that older recovered project and advanced its session epoch without reporting the unsupported newer work. The source-quality CLI instead rejected its stale pointer, obscuring the original Unsupported error. No future-format conversion or data loss is required to expose this misleading state.

Recovery now preserves and returns `ErrorCode::Unsupported` immediately for an unsupported decoded project schema or inspection-policy marker. It does not expose an older snapshot after encountering those format failures. Current public signatures and stored formats are unchanged; the header documents the distinction. The private verifier identifies the inspection-policy failure at its ancestry-check origin, avoiding message matching or an assumption that every Unsupported is a format failure. Parse/other supported corruption recovery, including bounded-read size failures, continues using the existing last-valid-generation path. No files are rewritten or removed by recovery, and the original underlying error remains available to callers.

The native Studio open implementation needs no source change: its existing refusal path returns before replacing `productionProject_`, changing the workspace/operator or incrementing `productionSessionEpoch_`. A refusal preserves an already open project, while a fresh controller opens no project. The durable writer also uses recovery before saving, so a save over an unsupported newest generation now returns Unsupported without appending history or changing the caller's project. The CLI now reports the actual unsupported-policy error directly rather than the later stale-pointer error.
