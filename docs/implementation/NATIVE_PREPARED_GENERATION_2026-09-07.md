## Visible job entry point

### Prepare from the current Designer draft

Cmd/Ctrl+Shift+P in Designer (also exposed as a semantic Prepare action) captures the current immutable recipe resource and the selected pose's style. It requires an open producer workspace/assignment and no recording, file work, active drag or producer worker. The score picker is checked against captured Designer and producer context after selection; cancellation leaves the view unchanged.

Successful dispatch returns to the producer view while background score inspection runs. A captured Designer resource allows inspection of nonempty regions on a score that has no saved procedural recipe. The ready status is `DESIGNER SNAPSHOT READY / SHIFT-P`. Shift+P then chooses region/destination through the existing flow; region labels identify the captured recipe/style and the destination dialog identifies a frozen Designer snapshot. The selection itself owns the resource through preparation. Later Designer changes do not update or silently recapture this job input.

The resulting package uses the explicit frozen-recipe preparation path described in `GENERATION_JOB_PACKAGE_2026-09-07.md`. No draft save, score rewrite, source approval, audio generation or producer assignment is implied by preparation. Generation remains a separate retained-job action and admission retains original expectations.

The added controller integration checks plain-score rejection without an explicit recipe, successful discovery with the frozen draft, retention of recipe identity through the selection and preparation worker, reloadable package identity and unchanged producer state. The new visible Designer-to-producer handoff remains live-unverified; earlier saved-score live QA is not evidence for this new action.

### Saved-score preparation UI

Shift+P now opens a saved `.seam` score picker. The existing worker reads at most 16 MiB, decodes the owned bytes and discovers up to 64 nonempty regions on tracks with saved procedural recipes. It returns track/region IDs, readable bounded UTF-8 labels, exact score SHA-256 and the captured workspace epoch/generation/selection. No recipe loading or score decoding occurs in paint or the dialog handler. After `SCORE READY / SHIFT-P PREPARE`, Shift+P again opens an accessibility-labeled AppKit region popup followed by a new job-folder destination panel. Cancellation consumes the transient selection and restores the prior status; another Shift+P starts score selection again.

Each dialog boundary rechecks recording and the captured workspace context. The preparation worker rereads bounded score bytes and requires the selected digest before decoding them. Even a semantically neutral byte change rejects without creating the requested job directory. Original recipe and producer expectations remain enforced separately. The destination name (without `.seamjobdir`) becomes the job ID and must meet the existing ASCII job-ID rules; the default is `generation-job`. Existing destinations are not replaced. The resulting folder contains `job.seamjob`, selectable through Cmd/Ctrl+Shift+I to generate and collect unapproved material.

This is a two-action asynchronous flow, not an automatic modal dialog launched from paint. AppKit region selection is implemented; other platforms explicitly return unsupported for that popup, although Win32 destination routing is source-updated. A fresh 720×520 synthetic-input Release run exited 0 with generation 4, approved 0 and no input callbacks/frames; the shortcut label fits in its inspected Retina capture (`/private/tmp/seam-studio-job-qa.gvOic0/preparation-shortcut.png`, temporary). Full keyboard/picker/popup/destination interaction and multi-region visual qualification remain unverified.

### Background preparation operation

`beginGenerationPreparation(scorePath, trackId, regionId, directory, jobId)` prepares a package for the selected planned take using the shared saved-score API. It captures the Studio model and assignment, verifies the recovered durable workspace still matches, and performs score/recipe loading and package writing on the existing single worker. Busy selection/save guards and stop/join lifetime handling apply. Success reports `JOB PREPARED / NOT GENERATED` without replacing the model or clearing manual inspection/undo state. It does not render, import, reserve an assignment or approve a take. The caller-specified directory contains the durable `job.seamjob` reference for later generation.

Cancellation is checked before work, after recipe loading and before package writing. Package publication itself completes without mid-write interruption, so a late cancellation does not hide a successfully prepared package. A concurrent producer edit after the initial check can make the frozen request stale; subsequent generation/collection retains the original expectation and rejects it rather than refreshing it. This is not an interprocess reservation.

Controller tests inspect and consume a score selection, verify region IDs/context, reject changed score bytes, prepare/reload the package with no output audio or producer mutation, enforce busy guards, and reject a previously changed durable workspace before creating the output directory. A pre-cancelled shared preparation request creates no directory. The visible flow above now invokes this operation; full interaction qualification remains open.

Cmd/Ctrl+Shift+I opens an OpenGenerationJob file dialog filtered to `.seamjob`. Newly prepared job directories include `job.seamjob`, a bounded reference containing the directory and original manifest SHA-256. Studio loads this reference rather than calculating a replacement digest from the selected manifest. Plain Cmd/Ctrl+I retains manual candidate import. Both shortcuts are shown in the intake panel.

The action refuses busy work or an armed/pending recording, stops audition, captures workspace epoch/generation/selected row before the dialog, rechecks that context and recording state after selection, and then starts the existing background controller operation. Small reference-file parsing occurs in the action handler, not paint; score/job loading and generation remain on the worker.

Reference v1 has exactly `formatId: com.project-seam.generation-job-reference`, `schemaVersion: 1`, `directory` and `manifestSha256`. It is limited to 8 KiB, depth 2, 12 nodes, 4 fields and 4,096-byte strings; invalid hashes, empty/control-character paths and malformed shapes reject. Relative directories resolve against the reference file. The user-selected reference is an unsigned trust input, not an authenticated signature; editing both reference and package is not prevented by a retained hash inside that reference. Existing jobs without references remain usable through the original digest-based CLI/API.

`VoicebankStudioController::beginPreparedGenerationJob(directory, manifestSha256, occurredAtUtc)` starts work for the selected producer assignment using a retained job digest. It shares the existing single-worker busy guard, stop source, owner-thread polling and shutdown join lifecycle with candidate import. Selection, saves and other conflicting controller operations remain blocked until the future is collected. Job loading, rendering and producer IO occur on the worker, not in paint.

The worker owns a producer snapshot. It verifies job identity and selected coverage/pitch/prompt, compares the captured model with the currently recovered durable workspace, and checks the planned take/original expectation before fresh generation. It runs the existing locked/recoverable worker and uses the guarded canonical importer. Publication still depends on the writer-locked expected generation; external edits cannot be silently merged into an old result. Error returns preserve the visible model, and successful collection adopts the committed project and refreshes candidate markers on the owner thread.

Already-collected requests use historical recognition. The worker returns an unchanged result/status, so polling does not replace the model or clear manual bounds, waveform/pitch inspection caches or marker undo history. A changed durable workspace is rejected rather than silently replacing the Studio's captured state. No review or approval is inferred from completion.

The existing Escape/finish/destructor paths request stop and join this future. Committed producer publication is not rolled back by a late cancellation; published job output can remain for verified reuse. This does not yet qualify hardware recording interactions or arbitrary cancellation timing in the native app.
