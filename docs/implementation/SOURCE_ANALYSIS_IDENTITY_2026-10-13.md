## Code contract and migration

1. **Native producer — `apps/seam-voicebank-cli/main.cpp`, `analyzeCommand`.** Read one size-limited source byte snapshot, decode that snapshot, and hash the same bytes. The original native WAV byte ceiling is preserved. Emit `formatId: com.project-seam.voicebank-analysis`, integer schema 2, `sourceSha256` and `pitchAnalysis`. Direct correlation and CompleteWindows coverage are selected explicitly. Configuration is read from the actual `PitchConfig`: window 2048, hop 256, 60–1200 Hz, voicing threshold 0.32. `kDirectPitchAnalysisAlgorithm` in `pitch.hpp` names `direct-autocorrelation-v3`; the separate FFT identity remains unchanged.
2. **Consumer — `proposal_rows` and `prepare`.** New preparation requires plan schema 2 and the exact full analysis contract, analysis format/schema/configuration, source digest, path/extent and complete ordered frame grid. A voiced frame must have finite F0 in 60–1200 Hz; an unvoiced frame must have zero F0. High-confidence unvoiced frames break a run. Existing confidence, cents, minimum-duration, edge guards, input limits and exclusive-output behavior remain in force.
3. **Outputs — `cuts.json` schema 2.** Retain the complete analysis contract with source/analysis/derived/PCM hashes and exact intervals. All assignments, review states, actor registration, rights clearance and bank admission remain unset or unapproved.
4. **Historical artifacts.** Schema-1 plans and unversioned analyses cannot generate new cuts. Regenerate with the current CLI into a separate directory and write a separate plan. Historical plans, analyses, cuts and audition files remain unchanged. The FFT training extractor uses a different method and frame-coverage contract and cannot substitute for this Direct producer.

These JSON declarations reject incompatible or accidentally stale data; they do not authenticate an unsigned caller or prove that a claimed algorithm actually ran. Retained executing binaries, source snapshots and command receipts supply the local execution evidence. They also do not establish true pitch, phonetic suitability or performer permission. Aliases and upper-bound voicing losses documented in [pitch limits](PITCH_LIMITS_DISCLOSURE_2026-10-13.md) remain relevant.
