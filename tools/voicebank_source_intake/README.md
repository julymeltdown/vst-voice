# Source-bound sustain cut proposals

`prepare_sustain_cuts.py` prepares **unassigned, unapproved** straight sustained-vowel material from original mono PCM16 WAVs and matching `seam_voicebank_cli analyze` output. It copies PCM intervals into new WAV containers without resampling, normalization or pitch changes. Ancillary RIFF chunks are removed and that change is recorded. It does not register a producer, import a workspace, assign Japanese phonemes, qualify pitch layers or approve any source rights.

```sh
python3 tools/voicebank_source_intake/prepare_sustain_cuts.py \
  --plan /absolute/path/to/cohort-input.json \
  --output /absolute/path/to/new-output-directory
```

The output parent must exist. An existing output is refused. All bound input files must be below the plan directory, without traversal or symlinks. New plans have schema version 2, a `license` record with relative `path`, lowercase `sha256`, non-empty `sourceUrl` and `attribution`, and 1–32 `sources`. Each source has a unique safe `id`, `sourceVowel` (a/e/i/o/u), `sourceTechnique: straight`, and `audio`/`analysis` records containing relative `path` and exact SHA-256. Repeated original audio hashes and duplicate JSON keys are refused. These vowels are source labels, not a language mapping.

`analysisContract` must be exactly `{"command":"seam_voicebank_cli analyze","algorithm":"direct-autocorrelation-v3","windowFrames":2048,"hopFrames":256,"coverage":"CompleteWindows","minimumHz":60,"maximumHz":1200,"voicingThreshold":0.32}`. The native producer reports analysis format `com.project-seam.voicebank-analysis`, schema 2, the same pitch configuration under `pitchAnalysis`, and the SHA-256 of the exact held byte snapshot it decoded. New preparation requires all of those fields. Keep the executing binary and command receipts too; these declarations do not authenticate an unsigned caller's history. An analysis's source path must still resolve to the bound original WAV. A relocated corpus needs fresh matching analyses, not silently rewritten analysis identity.

Legacy unversioned analyses and schema-1 plans cannot produce new cuts: regenerate analyses using the current CLI and write a separate schema-2 plan/output. Existing historical cuts, plans and analyses stay untouched. New `cuts.json` uses schema 2 and retains the complete analysis contract; the FFT training extractor has a different method/coverage contract and cannot be substituted here.

The tool validates byte hashes, mono PCM16 extent, matching analysis/source identity, a complete ordered hop grid, finite measurements and frame bounds. Voiced F0 must be within 60–1200 Hz; unvoiced F0 must be zero. High-confidence unvoiced frames remain a gap, not an accepted note. A proposal needs contiguous voiced frames at confidence ≥0.90, within 40 cents of one observed MIDI note. Rejected frames break the run. One full analysis window is removed from each edge of its measured support; the remaining cut must be at least 0.20 seconds. For each source and observed MIDI, only its longest qualifying interval is proposed. Short cuts and these thresholds are engineering choices, not bank QC or listening acceptance. In-range estimates can still be aliases; musical/phonetic/listening qualification remains independent.

Output consists of original-PCM cut WAVs, `cuts.json`, the exact `intake-plan.json` and hash-bound `license-source.txt`. `cuts.json` retains source/analysis/derived/PCM hashes, frame intervals, sample rate, measured pitch/confidence, source labels, attribution and change notices; it contains no absolute plan-directory path. Resolve relative input records against the separately retained plan directory for local reproduction. Fresh analyses after relocation may change their hashes. Every assignment/review/admission remains unset or unapproved. No draft inventory is generated. Malformed inputs print a refusal to stderr and exit 2. An I/O failure can leave an exclusively owned partial directory with `INCOMPLETE`; preserve and investigate it rather than importing it.

Run `python3 -m unittest tests.test_voicebank_source_intake -v`, or configured CTest `seam_vocal_source_intake_tests`. The tests verify original PCM preservation, repeat byte determinism, separation of notes/confidence gaps, specific stale/hash/format refusals, repeated-source/JSON-key refusal, controlled large-number/deep-JSON exits, partial-write markers and occupied-output preservation. The actual female VocalSet run and its language/rights holds are recorded in [the preparation report](../../docs/implementation/FEMALE_VOCAL_COHORT_PREPARATION_2026-10-13.md).

## Unassigned English speech phone donors

`prepare_phone_donors.py` copies explicitly requested spans from original speech WAVs and hash-bound FestVox end-time labels. The labels remain automatic and unreviewed. It does not translate `jh` to `j`, infer stress or pitch layers, or create a producer workspace, bank assignment or approval.

```sh
python3 tools/voicebank_source_intake/prepare_phone_donors.py \
  --plan /absolute/path/to/phone-plan.json \
  --output /absolute/path/to/new-donor-directory
```

The plan has exactly `schemaVersion: 1`, `documentKind: SourceLabelDonorPlan`, `language: en`, `labelContract`, `license`, `sources` and `spans`. `labelContract` is exactly `{"format":"festvox-end-times-v1","annotationStatus":"AUTOMATIC_UNREVIEWED","timeUnit":"seconds","boundaryRule":"ceil-seconds-times-sample-rate-v1"}`. `license` contains only relative `path`, lowercase `sha256`, nonempty `sourceUrl` and `attribution`; its original UTF-8 text is copied unchanged. Each of 1–32 sources contains only a unique safe `id`, `sourceType: speech`, and `audio`/`labels` records with relative `path` and `sha256`. Paths stay below the plan directory without symlinks/traversal. Repeated source audio hashes are refused for this one-corpus preparation route; this does not change the producer model's separate-source ownership rules.

Each of 1–4096 `spans` contains only `sourceId`, a zero-based integer `firstLabelIndex` and integer `labelCount` from 1–3. The index counts data rows, excluding comments/blank lines. A label row is `end-seconds opaque-column source-phone`; the next row starts at the preceding endpoint. Endpoints must be bounded decimal text, nondecreasing and within the WAV duration. The opaque integer column is retained, not interpreted as confidence. The boundary rule uses exact decimal arithmetic and `ceil(time * sampleRate)` at both ends: PCM sample index `n` belongs exactly when its point `n/sampleRate` is within the half-open label interval. Adjacent cuts therefore share a boundary; they neither overlap nor omit a sample at a fractional endpoint. Empty selected spans are refused, even if a zero-duration source annotation was retained.

Only standard RIFF/WAVE mono PCM16 at 8–192 kHz is supported. The complete RIFF extent, chunk bounds/padding, unique format/data chunks and PCM geometry are validated. Audio snapshots are at most 64 MiB each and 128 MiB in total; requested copied PCM is at most 128 MiB. Plans/label files are at most 1 MiB each, and label files have at most 16,384 data rows. Every input/span is validated before output creation. Output reuse is refused. An I/O failure preserves a new owned folder's `INCOMPLETE` marker.

Output contains canonical mono WAVs, `donors.json`, the unchanged `intake-plan.json` and `license-source.txt`. Each proposal retains source audio/label hashes, raw phone annotations and decimal endpoints, exact original frame interval, copied PCM hash and derived WAV hash. `nonzeroPcm` reports only whether any PCM byte is nonzero; a silent pause may be retained. No audibility or linguistic judgment is inferred. Ancillary WAV chunks are removed, with an explicit change notice; no resampling, normalization or pitch shift occurs. All phonetic/pitch/listening reviews and bank admission remain unset or unapproved. Relative input bindings resolve against the separately retained plan directory.

Run `python3 -m unittest tests.test_phone_donor_intake -v`. The existing CTest intake entry now runs both preparation suites. The [actual SLT cohort report](../../docs/implementation/FEMALE_PHONE_DONOR_PREPARATION_2026-10-15.md) records real source copies, deterministic outputs and native reader checks.
